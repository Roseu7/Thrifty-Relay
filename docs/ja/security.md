# セキュリティポリシー

ThriftyRelayは開発中で、第三者によるセキュリティ監査を受けていません。
登録済みの受付ポリシーがCodexのサンドボックスを選びます。
未登録の場合は、ThriftyRelayを実行するアカウントの権限で`danger-full-access`を使います。

## サポートするバージョン

タグ付きのリリースはまだありません。
セキュリティ修正は`main`の最新コミットに入り、過去のコミットは個別に修正しません。

## 脆弱性の報告

脆弱性はGitHubの非公開の脆弱性報告で報告してください。
リポジトリの**Security**タブを開き、**Report a vulnerability**を選びます。
公開のissue、pull request、ディスカッションでは報告しないでください。
フォームが使えない場合は、脆弱性の詳細を含めずに、非公開の連絡先を求めるissueを開いてください。

有用な報告には次を含めます。

- テストしたコミットとローカルの変更
- プラットフォームと、関係するコマンドまたはMCPツール
- 偽のデータを使った再現手順
- 発生したことと期待したこと

問題を実証したのか、疑いの段階なのかを書いてください。
トンネル用APIキー、資格情報、トンネルID、セッションデータ、タスクストア、プロセスの環境変数を添付しないでください。
自分が所有しているか、テストの許可を得たホストとその導入環境だけを対象にしてください。

問題の確認と修正の準備ができてから、メンテナーと公開日を合意してください。

## 対象範囲と信頼モデル

このポリシーの対象はリポジトリのコードです。
MCPツール、CLI、setupとdoctor、タスクの永続化、受付ポリシーの処理、スコープ付きリース、復旧、実行スーパーバイザーを含みます。
第三者提供のバイナリ、OpenAIのサービス、ホストクライアントの制御には、それぞれの報告経路があります。
依存関係が関係する場合でも、ThriftyRelayの統合上の不具合は対象に含まれます。

<a id="worker-permissions"></a>
### ワーカーの権限

CodexとMCPツールは、ホスト利用者の権限で、登録された受付ポリシーが選ぶワーカーの実効サンドボックスに従って動作します。
公開Codex要求は明示的な`permissions=full-access`を要求し、`readOnly=true`を拒否します。
登録済みポリシーはワーカーのサンドボックスを狭める場合があります。
cwdまたは書き込みスコープは受付を制御します。
OS上の書き込み境界は作らず、利用者の権限も広げません。

手動のエディター、関係のないツール、別のタスクストア、切り離されたジョブ、外部サービスは、連携したリースの排他から外れます。

<a id="admission-policy"></a>
### 受付ポリシー

受付ポリシーの登録は、別のローカル管理者操作です。
setupは登録しません。
`WARN / POLICY_UNREGISTERED`は、ポリシーの適用が無効な従来の動作を意味します。
検証できない既存の登録は受付をブロックし、doctorは`WARN / POLICY_UNVERIFIED`を報告します。

doctorのWARNは終了コード0を返すことがあります。
終了コードは診断結果として扱い、セキュリティの承認とはみなしません。
ポリシーの適用と宣言の違いは[受付](admission.md)にあります。

<a id="credentials"></a>
### 資格情報

トンネル用APIキーはWindows Credential Manager、Linux Secret Service、macOSのログインキーチェーンに保存されます。
一時的な`THRIFTYRELAY_RUNTIME_KEY`は保存されず、その実行だけ保存元を上書きします。
トンネルは環境で`CONTROL_PLANE_API_KEY`を受け取り、MCPのブートストラップはサーバーを読み込む前にトンネルの資格情報と上書きを削除します。
実行時の設定、トンネルの引数、実行ログは秘密情報の保管場所ではありません。
ただしmacOSのバックエンドは`security`のargvで秘密情報を書き込むため、書き込み中はプロセスの検査から見える可能性があります。

<a id="local-controls"></a>
### ローカルの保護

同じ利用者として動作するプロセスは、起動時の環境、ファイル、資格情報ストアの項目を検査できます。
資格情報の除去は、MCPの子プロセスへの偶発的な継承を防ぎます。
状態パス、所有者、権限、ファイル種別の検証は、偶発的な開示や置き換えを減らします。
TTYの確認と監査記録は運用上の証拠になります。
PCへのフルアクセスを持つプログラムは、これらを迂回できます。

## Skill

起動時のカタログは、`~/.codex/skills`のグローバルなユーザー管理のSkillを読みます。
メタデータと本文は信頼しない作業用のデータであり、権限を追加しません。
読み込む範囲と`config.toml`で無効にする方法は[Skill](skills.md)にあります。

## 既知の制限

<a id="tool-input-validation"></a>
### ツール入力の検証

ツール呼び出しごとに、配列の要素とオブジェクトの項目を、入れ子も含めて合計10,000個まで受け付けます。
MCP SDKがツールのスキーマを検証する前に、この上限を確認します。
Desktop Commanderは引き続きZod 3を使っており、[GHSA-mrhx-c7xc-m3w5](https://github.com/advisories/GHSA-mrhx-c7xc-m3w5)の影響が残ります。
入力上限でコレクションの検証量を制限していますが、依存関係の監査では元の問題が報告されます。

<a id="desktop-commander-network-requests"></a>
### Desktop Commanderの通信

ThriftyRelayは、Desktop Commanderを`DESKTOP_COMMANDER_DISABLE_TELEMETRY=1`を付けて起動し、利用状況のテレメトリーを止めています。
ただし、Desktop Commanderは起動時と動作中に定期的に、`desktopcommander.app`から機能フラグを取得します。
この通信は、テレメトリーの設定では止まりません。

<a id="images-and-output"></a>
### 画像と出力

画像の内容はテキストの秘匿化の対象外です。
スクリーンショットや写真に秘密情報が含まれる場合があるため、意図して公開した画像だけを読んでください。

テキストの秘匿化は既知のパターンを対象とします。
それ以外の文章やファイルに秘密情報がないか、モデルの出力とサードパーティのツールを確認してください。

<a id="process-ownership"></a>
### プロセスの所有権

プロセスの同一性確認と終了はベストエフォートです。
次の場合は所有を証明できないことがあります。

- PIDの再利用
- 子孫プロセスの証拠の不足
- `ss`や`lsof`の出力が取得できない、または信頼できない

所有を証明できなければ、無関係なプロセスは終了しません。

PIDがなくても、切り離された作業が動き続ける場合があります。
キャンセルと復旧は、すでに生じた外部への影響を残します。
結果が不明な書き込みを自動で再試行しないでください。

<a id="scoped-execution"></a>
### スコープ付き実行

スコープ付きリースとローカル復旧は実装済みです。
実際のスコープ付き同時実行の展開は、独立した統合テストが完了するまで保留しています。

`expected_files`と作業ディレクトリのハッシュは、レビュー用の証拠です。
受付を許可せず、すべての副作用を列挙するものでもありません。

<a id="windows-process-control"></a>
### Windowsのプロセス制御

稼働中のWindowsホストには、保護された`mcp:restart`手順を使ってください。
基本のライフサイクルCLIは、一部の書き込みロックの保護を省きます。

次の動作は確認が必要です。

- ターミナルを閉じたあとのクリーンアップ
- 最高実行レベルで登録されたタスクの、管理者権限なしでの制御

<a id="linux-and-macos"></a>
### LinuxとmacOS

POSIXのバックグラウンド実行はターミナルを閉じても続き、ログアウトや再起動で止まる場合があります。
setupは自動起動の設定を追加せず、ThriftyRelayはUID 0を拒否します。

macOSのキーチェーンとMac実機での動作は、資格情報の書き込み時にコマンド引数から秘密情報が見える制限を含めて確認が必要です。

<a id="authentication-and-host-checks"></a>
### 認証とホストの確認

CodexアダプターはファイルベースのChatGPT認証を要求します。
キーリングだけの認証との互換性は未解決です。

次の項目は、オフラインのテストとCIとは別に確認します。

- 稼働中のMCPホスト
- MCP Appsの描画と承認の操作
- 実際のCodexの承認フロー

<a id="uninstall"></a>
### アンインストール

アンインストールは、記録された資格情報の項目、設定、ランチャー、ログ、実行状態を削除します。
次の場所には複製が残る場合があります。

- バックアップ
- プロセスのメモリ
- 別名で保存された資格情報の項目

タスクストア、管理者が登録した受付ポリシー、無関係なツールと資格情報は保持します。

LinuxのSecret Serviceの削除はベストエフォートです。
`secret-tool clear`のあとにも一致する項目が見える場合、アンインストールは停止します。
ロックされただけの項目は存在しないように見える場合があります。

<a id="recovery-records"></a>
### 復旧記録

リクエストの重複防止記録、復旧の証拠、監査記録は一緒に保管してください。
拒否を回避するためにロックを削除したり、復旧記録を変更したりしないでください。
[ガイド付き復旧](recovery.md)を使い、部分的な失敗の監査IDを保持してください。
